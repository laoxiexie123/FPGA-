# 编码器位置与速度模块

[encoder.v](../src/encoder.v)集中读取电机AB编码器和计算10ms窗口速度。位置逻辑来自重建时v2.2的encoder_guard，测速算法来自其顶层。固定判稳系数4，不使用cfg总线。

## 接口与职责

- clk_50m：50MHz单一内部时钟；rst_n：低有效异步复位，集成时同步释放。
- enc_a/enc_b：外部正交输入，分别经两级同步，再共同判稳。
- zero：同步清位置、溢出和测速历史，重新建立相位；不清非法跳变累计次数。
- tick_10ms：同域单拍窗口使能，必须每10ms一次；外部统一提供以保持系统时基。
- position_q：signed32四倍频位置，单位count；speed_q：signed32窗口速度，单位counts/s。
- invalid_count_q：非法相序累计，饱和；overflow_fault_q：位置溢出锁存。

模块不产生电机命令，也不决定故障后是否停止。速度仅窗口差分，没有添加IIR或移动平均；后续位置D仍需按原控制算法处理，不能直接用此速度替代。

## 保持的边界与拍数

```text
AB输入 → 两级同步 → 共同候选判稳 → 相邻格雷码译码 → 位置
                                                   ↓
                              外部10ms使能 → 位置差×100 → 速度
```

1. 正方向00→10→11→01→00，每步+1；反向每步-1。一电气周期共4count，不定义物理顺逆时针。
2. 候选改变当沿稳定计数置1，后续同相位累加到4，再下一判定沿才接收。固定参数后内部计数缩至3位，0..4范围与旧实现一致。
3. 复位释放后先4拍预热；首次稳定相位只建基准，不计位置。短于判稳条件的真实变化也可能被滤除。
4. 双位跳变不改位置，但将其记为已接收相位并将非法计数加1，防止同一事件重复记录。
5. 到signed32端点继续向外时保持并锁溢出；之后反向合法步仍计数，故障不自动解除。非法计数达到全1后保持。
6. zero优先于相位处理和测速tick。zero持续高时反复清零，但同步链及预热持续推进。松开后先重新建立稳定相位。
7. 测速采用signed33位置差乘40位常量100，检查后饱和至signed32。zero清测速参考避免虚假清零尖峰；不重启外部tick相位。
8. 位置接受沿与tick同沿时，测速读取旧位置，更新后的步数计入下一窗口，保留原非阻塞赋值语义。

不添加position_valid握手或ready输出，以免改变旧消费者的接口时序；消费者须遵守复位和zero后建立基准的合同。速度在tick后更新，其余拍保持，不代表瞬时转速。

## 验证与限制

[测试台](../tb/tb_encoder.v)、[运行脚本](run_encoder_tests.py)负责旧编码器＋旧顶层速度影子对照、独立模型及判稳/清零/饱和边界。结果见[encoder_test_results.json](encoder_test_results.json)。

- Verilator 5.050严格--lint-only --Wall通过，零警告、无豁免。
- Verilog2005/2012分别通过1513315个运行周期、1513329次检查，运行期间相关源码哈希稳定。
- 覆盖全部16种AB相位组合、3个真实500000拍窗口、6个速度饱和边界、12000随机周期和5次异步复位。
- 定向断言检查引脚切换后第6个系统沿尚未计数、第7沿才计数（包含同步延迟）；计数与tick同沿速度读取旧位置，zero与二者同沿时优先清零。
- 独立相位/周期/64位速度模型及旧模块链逐拍一致。
- 源码139行，最长81列，无Tab。验证达到II级数字仿真，非形式证明或硬件验证。

边界溢出使用测试台对旧新寄存器和模型同步注入，再执行实际合法相位或tick；不通过运行数十亿步制造端点。实际10ms窗口测试使用500000拍，另有主动窗口使能验证同沿边界，不能将主动短tick解释为真实速度。

此次只新增模块、测试与工程登记，没有改变旧工程及已完成ADC/驱动源码。未添加引脚/时序约束、未综合或硬件加载；两级同步数字仿真不证明物理MTBF和片外信号质量。
