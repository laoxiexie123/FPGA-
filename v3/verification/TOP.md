# 本地按键顶层

## 本次确认范围

用户确认SW1启动、rst_n复位即停，SW4只保留将来的串口发送触发，不实现串口。沿用v2.2的XH1电机B通道、1A/1B编码器、ADC接线和器件GW2A-LV55PG484C8/I7（revision C）。按用户后续指定，直立零点改为参考for_rip_top/src/pid_ctrl.v的实际路径：第85行theta_rr=theta_r+135，第93行err=theta_rr-3100，等效原始四倍ADC零点为2965（3100-135），替代先前v2.2默认1952。第1行balance_theta宏2950没有参与实际误差计算，不使用该未生效宏。参考ADC.v第28行将10位ADC左移2位，第68行对16点求平均，确认两工程零点使用同一四倍ADC单位；这里只迁移零点，不迁移参考工程的增益、误差极性或平行环结构。不是本轮实测或自动校准。

## 分工与数据流

- top只做复位释放、1/5/10ms使能、按键请求、固定本地运行许可和模块连接，不重写PD或起摆状态机。
- key_filter对按键两级同步，按下/释放均消抖。默认1000000个50MHz周期，即20ms；长按只发一次脉冲。复位时按住SW1，必须先稳定释放再按下，防止复位释放后自行启动。
- adc_pend平均/滤波/观测结果送swing_control，Q8/x4同源历史送balance_control；encoder位置与速度分别供PD及起摆准入/安全检查。
- swing_control是唯一电机命令监督器：平衡命令和commit回传起摆，起摆最终命令送motro；不在top叠加P/D。
- SW4的transmit_request为内部预留，不作为电机运行条件、不导出诊断接口。没有消费者时综合可优化掉这一条按键逻辑。

## 时钟、引脚与CDC

| 项目 | 来源与处理 |
| --- | --- |
| clk_50m | 旧约束M19，50MHz，top.sdc设20ns主时钟 |
| rst_n | 旧约束AB3，低有效，异步拉低、两级同步释放；不是安全级急停 |
| SW1 / SW4 | T18 / T20，旧key_sw[0] / key_sw[3]，LVCMOS15、Bank 1.5V |
| 编码器1A / 1B | Y20 / AA20，LVCMOS33，encoder内已有两级同步 |
| 电机 | XH1的B通道，V14/V15/AA17；A通道强制0/0/0 |
| ADC | 沿用v2.2/src/pos_loop.cst的G18/H20与10位数据引脚 |

全部内部逻辑同一50MHz域；tick只作使能。ADC输出时钟不是额外内部域，ADC已有采样关系不改变。按键同步在key_filter内部，top不重复同步。SDC仅沿用已确认的系统时钟和异步输入例外；ADC片外建立保持与板延迟没有确认值，不编造input_delay，也不能声称板级IO时序收敛。没有确认STBY物理引脚，因此不导出自动分配的STBY端口。

## 运行许可

- 上电停止。数据尚未建立只阻止启动，不在待机锁成传感器失效故障。
- 连续满足启动条件100个1ms使能后，新的SW1按下事件才准入；过早按下被丢弃，不排队、不长按自动补启动。
- 启动条件：平均值新鲜、ADC滤波已有初值，无模块故障，位置绝对值不大于10000 counts、摆臂速度绝对值不大于200 counts/s。起摆不额外要求pendulum_valid，避免破坏旧模式3的角度/轨端豁免；捕获和丢失判断仍由swing_control读取pendulum_valid，observer_fault始终是硬故障。
- 运行保护沿用旧C08/C09：臂速不大于2200 counts/s、位置不大于10000 counts。ADC最大样龄20ms由adc_pend维护。
- 起摆阶段沿用旧模式3角度/轨端豁免；正常立摆恢复旧C07/C18阈值：原始ADC相对当前零点2965的四倍误差不超过400，ADC码处于[10,1013]。
- 任一运行测量失效或ADC观测/编码器溢出/PD/起摆故障立即撤销motor_permitted，并锁存停机；motro在故障信号可见后的下一50MHz上升沿关闭PWM和方向，最多再等1拍20ns，不等待载波周期。故障源在某沿NBA才置位时不声称该沿已关物理PWM。数据恢复或再按SW1不会重启，只有rst_n复位后重新按下才能运行。
- rst_n既停止又清模块历史及故障，编码器软件原点也回到复位定义；不等同于保留原点的独立软停止。
- 不伪造串口心跳、48项配置完整标志或回读：本工程固定常量、本地按键，不迁移UART/UI/轨迹/位置积分；未声称与旧完整top逐周期等价。

## 验证边界

I级：整机严格Verilator lint通过。II级：key_test_results.json中两种模式均通过参数1/4/1000000的独立按键模型，默认20ms按下/释放完整运行、无预置计数；top_test_results.json两模式各564274拍、208项检查，含真实10ms时基、SW1/SW4、8类锁停、轨端起摆豁免及真实PD捕获。顶层测试的100ms就绪窗口和按键20ms边界用计数预置加速，不冒充完整长等待。

III级历史证据：1952零点版真实Gowin整机综合成功，但估算Actual Fmax为25.761MHz，最差slack=-18.818ns，尚未满足50MHz。当前2965零点版仅重跑I/II级验证，不沿用旧综合源码哈希。瓶颈为supervisor/duty_q至motor/pulse_width_q的电机脉宽换算路径。详细资源、警告、源码哈希和边界见[top_synthesis/README.md](top_synthesis/README.md)，不沿用此前balance单模块资源，也不声称时序收敛。

不做布局布线、下载、Flash固化或板级稳定性结论。真实启动前仍需核对实机零点、机械方向、ADC接口时序及可立即断开的电机动力电源。
